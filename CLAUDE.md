# Arena Survival: Build Spec for Claude Code

Oct 27, 2026 · @Acey

## Brief

Build the playable prototype of an original Roblox arena survival game: 2–24 players spawn around a central Supply Spire, loot, fight and outlast a closing border until one is left. The prototype answers one question with greybox art: is a round fun enough that testers ask for another?

In scope now:

- Lobby and queue with a 60-second start timer and three lobby sizes
- Round manager that runs every phase from countdown to results
- One greybox arena with spawn pads, the Supply Spire and loot crates
- Melee (spear, axe) and a bow; health and hunger
- The Collapse (closing border) and the Feast at five players left
- Spectator camera for knocked-out players
- Server-side bots so rounds can be tested solo

Out of scope now: shop and purchases, saved progress, final art and audio, Duos, Patron voting (stretch only, see Task list).

How to work:

- Do one task from the Task list at a time; commit after each passes its check.
- Put every tunable number in the Config module, never inline.
- Check the Roblox Creator Hub docs (create.roblox.com/docs) before using an API; never guess an API name or signature.
- Ask before adding any dependency not listed in Toolchain.

## Project layout

The prototype is one place: the lobby area and the arena live in the same server, and rounds start with whoever is in that server. Cross-server matchmaking comes later; don't build it now.

Game rules live in `src/shared` as pure Luau with no Roblox globals or services, so Lune can test them from the terminal. Pass anything random or time-based in as a parameter. Services in `src/server` are thin glue between those rules and the engine.

## Game rules and config

Create `src/shared/Config.luau` exactly like this; every number is a starting value to tune in playtests. The lobby size is picked from the human player count at round start, and its Collapse stage count sets round length: about 9 minutes for Full Arena, 7.5 for Skirmish and 4.5 for Showdown, plus the countdown.

```lua
--!strict
-- Every tunable number lives here. Starting values; tune in playtests.
local Config = {
	Queue = {
		WaitSeconds = 60, -- start with whoever is queued after this
		MinPlayers = 2,
		MaxPlayers = 24,
	},

	-- Chosen by LobbySize.luau from the human player count
	LobbySizes = {
		FullArena = { MinPlayers = 12, MaxPlayers = 24, ArenaRadius = 450, CollapseStages = 6 },
		Skirmish = { MinPlayers = 6, MaxPlayers = 11, ArenaRadius = 300, CollapseStages = 5 },
		Showdown = { MinPlayers = 2, MaxPlayers = 5, ArenaRadius = 150, CollapseStages = 3 },
	},

	Round = {
		CountdownSeconds = 20,
		ResultsSeconds = 15,
		FeastAtPlayersLeft = 5,
		SpawnRingFraction = 0.35, -- pads sit on a ring at this share of ArenaRadius
	},

	Collapse = {
		StageSeconds = 90,
		FinalRadius = 30,
		DamagePerSecondOutside = 5,
	},

	Survival = {
		MaxHealth = 100,
		MaxHunger = 100,
		HungerDrainPerSecond = 0.25, -- empty after about 6.7 minutes
		StarvingDamagePerSecond = 1,
	},

	Weapons = {
		Spear = { Damage = 25, Range = 10, Cooldown = 0.8 },
		Axe = { Damage = 35, Range = 7, Cooldown = 1.1 },
		Bow = { Damage = 30, Range = 150, Cooldown = 1.5 },
	},

	Loot = {
		TierWeights = { Common = 70, Rare = 25, Epic = 5 },
		SpireTierWeights = { Common = 30, Rare = 50, Epic = 20 },
		CratesPerPlayer = 3,
	},

	Bots = {
		EnabledInStudio = true, -- lets one person test a full round
		EnabledLive = false,
		FillTo = 8,
	},
}

return table.freeze(Config)
```

## Module specs

`RoundService` owns a four-phase loop and every other server module reacts to its phase changes.

1. **Waiting**: players gather in the lobby area; `QueueService` runs the queue timer.
2. **Countdown**: players are moved onto spawn pads and frozen for `CountdownSeconds`.
3. **Active**: Collapse stages run; when `FeastAtPlayersLeft` or fewer remain, epic crates spawn at the Spire once. The phase ends when one player is left.
4. **Results**: the winner is shown for `ResultsSeconds`, then everyone returns to the lobby and the loop restarts.

| Module | Responsibility |
| --- | --- |
| QueueService | Starts the queue timer once `MinPlayers` are in the lobby; starts at once on `MaxPlayers`; hands the roster to RoundService |
| RoundService | Runs the phases above; picks the lobby size via `LobbySize`; ends the round at one survivor |
| ArenaBuilder | Each round, builds a greybox disc sized to the lobby, the Supply Spire, spawn pads on a ring and crates; anchored parts, flat colors only |
| LootService | Rolls crate contents with `LootTable` and a seeded `Random`; opens crates through a server-side ProximityPrompt; holds every inventory on the server |
| CombatService | Checks each attack request (alive, cooldown, range, line of sight), applies damage from `Combat`, handles knockouts |
| SurvivalService | Drains hunger, applies starvation damage, restores hunger when food is eaten |
| CollapseService | Gets each stage's radius from `Collapse`, shrinks a visible wall, damages players outside it |
| BotService | Studio only: spawns R15 bots that loot the nearest crate, attack players in range and move inside the border |
| Remotes | Creates every remote, checks every argument's type and value, rate-limits each player |
| InputController | Maps keyboard, touch buttons and gamepad to attack, use item and sprint |
| HudController | Shows health, hunger, phase timer, players left and a Collapse warning |
| SpectateController | After a knockout, cycles the camera between living players |

| Remote | Direction | Payload |
| --- | --- | --- |
| RequestAttack | Client → server | weapon slot, aim direction |
| RequestUseItem | Client → server | inventory slot |
| PhaseChanged | Server → all | phase name, end time |
| StatsChanged | Server → one player | health, hunger |
| PlayersLeftChanged | Server → all | count |
| CollapseChanged | Server → all | radius, next stage time |
| KnockedOut | Server → all | who was knocked out, by whom |

## Rules for the code

These are hard rules; if a task seems to need breaking one, stop and ask.

Server authority

- The client sends intent only ("attack with slot 1 toward this direction"). The server decides hits, damage, loot, inventory and knockouts.
- Never trust a client value you can compute on the server: positions come from the server's copy of the character, items from the server inventory.
- Before writing any movement anti-cheat, read the Creator Hub docs for Roblox's built-in Server Authority feature and prefer it over custom code.

Remotes

- Every remote handler checks argument types, rejects NaN and out-of-range values, requires a unit-length aim direction, and ignores players who are knocked out.
- Rate-limit each player per remote; drop excess requests silently.

Code style

- `--!strict` at the top of every file; no `any` unless commented why.
- Rules in `src/shared` use no Roblox globals or services, so Lune can test them.
- Every tunable number comes from `Config`.

Content and IP

- Keep the Mild content label: no blood or gore. A knockout is a stylized burst of particles, then the player becomes a spectator.
- Never use Hunger Games names or terms in code, UI or assets: no Panem, District, tribute, Cornucopia, Capitol, Mockingjay, reaping or Gamemaker. Use Entrants, Supply Spire, Patrons, Collapse.
- Use only original assets or Creator Store assets cleared for use; no copyrighted music.

Mobile

- Every action must work with touch. Check each UI change in Studio's device emulator at a phone size.

## Task list

Work top to bottom. A task is done when the quality gate passes and its check passes; verify playtest checks yourself through the Studio MCP server (start the playtest, read the console, take a screen capture), then commit.

1. **Scaffold.** Rokit tools, Rojo project, `selene.toml`, `stylua.toml`, and a `.lune/test.luau` runner. Check: the quality gate passes on the empty project and `rojo serve` connects in Studio.
2. **Config and LobbySize.** Check: specs cover 1, 2, 5, 6, 11, 12, 24 and 25 players, including out-of-range counts.
3. **RoundPhases and Collapse rules.** Check: specs show the radius shrinking every stage and reaching `FinalRadius` on the last one, for all three sizes.
4. **ArenaBuilder.** Check: screen captures show all three sizes with the right pad count and the Spire in the center.
5. **QueueService and RoundService.** Check: with bots on, the loop runs Waiting to Results and back twice with no console errors.
6. **LootTable and LootService.** Check: a spec of 10,000 rolls lands within 2 percentage points of each tier weight; crates open in a playtest.
7. **Combat and CombatService (spear, axe, bow).** Check: specs cover cooldown and range; in a playtest, a bot takes damage and attacks sent faster than the cooldown are ignored.
8. **SurvivalService.** Check: hunger empties within 5 seconds of the time Config predicts.
9. **CollapseService and the Feast.** Check: the wall is visible and shrinks on schedule; players outside take damage; epic crates appear once at five players left.
10. **BotService.** Check: a solo playtest with `FillTo = 8` finishes a whole round.
11. **Client controllers (input, HUD, spectate).** Check: every action works at a phone size in the device emulator.
12. **Playtest build.** Check: the full quality gate passes and the place is ready for a human test with 8–12 players.

Stretch: **Patron voting.** Only after 1–12 pass: knocked-out players vote each minute on a care package or a hazard. Ask before starting.
